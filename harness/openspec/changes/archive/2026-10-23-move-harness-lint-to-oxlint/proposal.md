# Proposal

## Why

The full `typescript()` preset of `@inflexa-ai/oxlint-plugin` gives 9567 reports on harness (`tmp/claude/lint/harness.md` section 3, taken with plugin 0.3.0; the pinned run is the authoritative list). Fixing them and moving the tools in one step is not reviewable, so the epic splits the work: this change (#609) moves the tools only, and each child issue of the umbrella #607 turns one set of rules back on with its fixes (#703, #705, #704, #707, #706, #708, #710, #709, in stack order). prov-kernel moved first (#606, PR #639) and gives the reference shape; the closed PR #676 attempted both halves in one branch and is the source of the config, lockfile, workflow, and text parts taken here — its rule fixes are not taken, because each child issue of #607 owns one set.

## What Changes

- harness installs `oxlint@1.85.0`, `oxlint-tsgolint@7.0.2003`, `@inflexa-ai/oxlint-plugin@0.7.0`, `@inflexa-ai/typecheck@0.7.0` and the `@typescript/native: npm:typescript@7.0.2` alias at exact versions — the same pins prov-kernel uses on main — and removes `eslint`, `@eslint/js`, `typescript-eslint`, `globals`, `eslint-plugin-neverthrow`, the `patchedDependencies` entry, and `patches/eslint-plugin-neverthrow@1.1.4.patch` (issue task 1). `typescript` stays the version 6 line that builds `dist/`.
- `harness/oxlint.config.ts` default-exports `typescript({ env: { node: true } })`, based on PR #676's file for the harness (the shape `prov-kernel/oxlint.config.ts` established), with the parts of `eslint.config.js` that carry over: the ban of `@inflexa-ai/tsprov` and `@inflexa-ai/tsprov/*` through `restrictedImports`; the `className` ban on `**/*.tsx` in an override that repeats the still-on `restrictedSyntax()` entries — the subset form the plugin's own typing prescribes, because an override replaces the options and the three lifted bans must not come back on `.tsx`; `no-console` on `src/**` with the path exemption for `src/lib/console-logger.ts` and `src/lib/console-logger.test.ts` (the pre-move test path of main); `typescript/no-unused-vars` with the four `^_` options; `typescript/switch-exhaustiveness-check` with `considerDefaultExhaustiveForUnions: true`; and the `.forEach` ban, carried by the preset default because `syntax` leaves `forEach` on (issue task 2).
- `typescript/await-thenable` and `typescript/no-confusing-void-expression` are off in the test files only: bun-types types `expect().rejects.toThrow()` as `void`, and the two rules give about 300 false reports there (issue task 3; the one exemption the umbrella's done-when keeps forever).
- `tsconfig.json` includes `scripts/**/*.ts`, so the typed rules and the type check command see the scripts with the real types instead of the default-options `error` type (issue task 4; PR #676's choice, taken with its config).
- Each other preset rule that has reports is off, and the comment on each off entry names the child issue that turns it on — `@inflexa-ai/test-placement` → #703; `typescript/no-unsafe-*` and `@inflexa-ai/no-conditional-spread` → #705; `@inflexa-ai/no-interface` → #704; `@inflexa-ai/require-assertion-safety`, `typescript/no-unsafe-type-assertion`, `@inflexa-ai/no-double-cast` → #707; `typescript/no-non-null-assertion`, `typescript/no-unnecessary-type-assertion`, `typescript/no-unnecessary-condition` → #706; the restricted syntax `regex`, `jsonParse`, `timers` → #708; `typescript/require-await`, `typescript/no-implied-eval` → #710; each remaining rule with reports → #709 (issue task 5, amendment comment). The `regex`, `jsonParse`, `timers` bans lift through the factory's own `syntax` option, the prov-kernel precedent shape.
- `bun run lint` runs `bun --bun oxlint`; `bun run typecheck` runs `inflexa-typecheck`; `harness/typecheck.config.ts` sets `must-use-result` with the `consumers` option `unwrapOrThrow`, `passGate`, `deliverNotice` and `keepSuspendingRefusal` — the same consumer list the patched ESLint wrapper knew — and turns `must-use-result` off for the test globs, with the comment that a child of #607 turns it on in tests, where each test asserts the Result instead of dropping it (the patched ESLint rule never saw a floating awaited `Promise<Result>` — a blind spot the type check command closes, with 77 reports on main's tree; the supervisor decision of this run scopes the tests out). `eslint.config.js` is deleted (issue task 6).
- The inline directives take their settled forms: `no-control-regex` at `src/input-sanitization.ts` becomes `oxlint-disable-next-line`; the four old `must-use-result` directives in `src/lib/result.test.ts` and `src/lib/hooks.test.ts` are deleted, because the test glob of `typecheck.config.ts` covers their sites and a dead directive is noise; and one new `typecheck-disable-next-line must-use-result` directive lands at `src/workflows/execute-analysis.ts:385`, carrying the reason of the adjacent comment — a ledger miss must not fail the run — stated once, in the directive (issue task 7, supervisor decision).
- The reports oxlint finds and ESLint missed are fixed — the full category, with the pinned run as the authoritative list: every `no-unsafe-optional-chaining` report (the pinned run gives 11 on main — the research-era inventory knew one, in `src/workflows/execute-analysis.test.ts` line 965, the `(failed?.error as string).length` expression; the others sit in `src/report-render` figure and gallery tests) and `no-misused-promises` at `src/loop/run-to-terminal.test.ts:58`. The rules stay on (issue task 8).
- `.github/workflows/lint.yml` changes: the job keeps the name `lint (harness)` (because `release-harness.yml:88` and `release.yml:70` wait for it), the ESLint step becomes the oxlint step, the typecheck step runs the type check command, and the job gains `actions/setup-node` with Node 24, which the command needs (issue task 9).
- Each text that names ESLint or `eslint.config.js` changes: `harness/CLAUDE.md`, `openspec/specs/structured-logging/spec.md` (through this change's delta), `src/lib/result.ts`, `src/sandbox/create-sandbox.ts`, `src/lib/console-logger.ts`, and `lint.yml` (issue task 10).

## Impact

- `harness/`: `package.json` and `bun.lock`, new `oxlint.config.ts` and `typecheck.config.ts`, deleted `eslint.config.js` and `patches/eslint-plugin-neverthrow@1.1.4.patch`, `tsconfig.json` (scripts include), `CLAUDE.md`, the six directive sites, and the two task-8 report sites.
- Root: `.github/workflows/lint.yml` (the harness job).
- `openspec/specs/structured-logging/spec.md` through the delta of this change.
- No rule reports are fixed outside the two task-8 sites: each other reporting rule stays off with its child-issue comment, so the child PRs of #607 own their fixes. No test file moves (`@inflexa-ai/test-placement` is off, #703 owns the move), no `interface` changes (#704), and `tsconfig.build.json` stays unchanged.
- Published surface: unchanged — the tools are devDependencies, `files` ships only `dist` and `NOTICE`, and the two task-8 fixes live in test files.
