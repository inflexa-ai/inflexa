# Design

## Context

harness is the second subsystem of the epic #611 that moves to oxlint. The typed programs were fixed first (#605): `tsconfig.json` includes all of `src` with `"types": ["bun", "node"]`, the build reads `tsconfig.build.json`, and `tsconfig.eslint.json` is gone. prov-kernel moved second (#606, PR #639) and is the reference: `oxlint.config.ts` default-exporting `typescript({ env: { node: true } })`, `typecheck.config.ts` with the `must-use-result` `consumers` option, `lint` = `bun --bun oxlint`, `typecheck` = `inflexa-typecheck`. The closed PR #676 did #609 and #607 in one branch; its head carries the same pins as prov-kernel on main, and its non-src files are the source of the config, lockfile, workflow, and text parts taken here. Its ~780 `src/` file changes (report fixes, the test move into `src/**/test/`, `tsconfig.build.json`, `scripts/refresh-fixtures.ts`) are not taken: each child issue of #607 owns one set. The local research `tmp/claude/lint/harness.md` holds the inventory (rule map with research-era counts); the pinned 0.7.0 run on this branch is the authoritative report list.

ESLint leaves nothing behind that oxlint and the type check command do not cover. The one typed rule outside oxlint's reach, `neverthrow/must-use-result`, runs in `inflexa-typecheck` on the same program, with the consumer list of the patched wrapper (`unwrapOrThrow`, `passGate`, `deliverNotice`, `keepSuspendingRefusal`) as its `consumers` option. The patched wrapper, its bun patch, and the ESLint stack that hosted them go away.

## Goals / Non-Goals

**Goals:**

- harness lints with `typescript()` of `@inflexa-ai/oxlint-plugin` 0.7.0 at the exact versions prov-kernel pins, and typechecks with `inflexa-typecheck`; no ESLint dependency, config, patch, or directive remains.
- Each preset rule that has reports on the pinned run is off, and the comment on the off entry names the child issue that turns it on. No report outside the two task-8 sites is fixed in code.
- `bun run lint` and `bun run typecheck` exit 0 in harness; `bun test` passes; the type check command gives the same `must-use-result` reports the patched ESLint rule gave — none on the tracked tree, with the four rewritten directives still suppressing their sites.

**Non-Goals:**

- No report fixes and no test moves: #703 owns `@inflexa-ai/test-placement`, #705 the `no-unsafe-*` family and `no-conditional-spread`, #704 `no-interface`, #707 the assertion-safety set, #706 the non-null and type-assertion set, #708 the `regex`/`jsonParse`/`timers` bans, #710 `require-await` and `no-implied-eval`, #709 each remaining rule.
- No lint change in cli, no change to the prov-kernel configuration, no `tsconfig.build.json` change, no version bump or publish.
- No `directive-guard` in the harness scripts — prov-kernel runs none either; the guard is a repository-policy decision outside this issue.

## Decisions

1. **Versions and scripts follow prov-kernel exactly.** `oxlint@1.85.0`, `oxlint-tsgolint@7.0.2003`, `@inflexa-ai/oxlint-plugin@0.7.0`, `@inflexa-ai/typecheck@0.7.0`, and `@typescript/native: npm:typescript@7.0.2` in devDependencies; `typescript` stays `^6.0.3`. `lint` = `bun --bun oxlint` (the TypeScript config loads under Bun, so the runner Node version never loads it); `typecheck` = `inflexa-typecheck` (the command runs under its Node shebang, because its TypeScript 7 dependency reaches Node `child_process` internals that Bun's spawn lacks — verified during #606).

2. **`oxlint.config.ts` is PR #676's config adapted to main, plus the off block.** Base: `typescript({ env: { node: true }, syntax: { regex: false, jsonParse: false, timers: false }, restrictedImports: [the tsprov ban with its message] })` with override blocks for the `^_` options of `typescript/no-unused-vars` and `considerDefaultExhaustiveForUnions` of `switch-exhaustiveness-check` on `**/*.{ts,tsx,js,mjs}`; `no-console` on `src/**`; the `no-console` exemption for `src/lib/console-logger.ts` and `src/lib/console-logger.test.ts` — the pre-move test path on main, not PR #676's `src/lib/test/` path; the vendored `js/recommended` set on `scripts/**/*.mjs` (the accepted drop from ESLint's full `js/recommended` on `.mjs` — for example `no-undef` and `no-unreachable` — is the same accepted regression prov-kernel and PR #676 carry); the `className` ban for `**/*.tsx` in a block that repeats only the still-on bans — `restrictedSyntax({ regex: false, jsonParse: false, timers: false })` with each `false` entry dropped, plus the JSX entry — because an override replaces the options of `eslint-js/no-restricted-syntax`, the plugin's own typing prescribes the subset form for a zone, and the three lifted bans must not come back on `.tsx` (a `.tsx` view holds regex literals today, for example `src/report-render/views/prose.tsx:34`); and the bun-types block (`typescript/await-thenable` and `typescript/no-confusing-void-expression` off) for `**/*.test.{ts,tsx}`. The `instanceofErrorAllowIn` entry of PR #676 names `src/lib/thrown.ts`, a file its own rule fixes created; on main the rule is off (#709), so the entry is absent. The `syntax` lifts carry the `#708` comment in the amendment's mapping.

3. **One final override block turns each reporting preset rule off, each entry commented with its child issue.** The block targets `**/*.{ts,tsx,js,mjs}` — the widest glob the preset itself uses. The pinned run is the authoritative list: after the config skeleton and the dependencies land, `bun --bun oxlint` is run, each rule id of its reports is mapped to its child issue — `@inflexa-ai/test-placement` → #703; `typescript/no-unsafe-call`, `-member-access`, `-assignment`, `-return`, `-argument` and `@inflexa-ai/no-conditional-spread` → #705; `@inflexa-ai/no-interface` → #704; `@inflexa-ai/require-assertion-safety`, `typescript/no-unsafe-type-assertion`, `@inflexa-ai/no-double-cast` → #707; `typescript/no-non-null-assertion`, `typescript/no-unnecessary-type-assertion`, `typescript/no-unnecessary-condition` → #706; `typescript/require-await`, `typescript/no-implied-eval` → #710; each remaining rule → #709 — and the entries repeat until the run reports nothing outside the two task-3.2 sites. Two rules never take an off entry: `no-unsafe-optional-chaining` and `typescript/no-misused-promises` — their single reports are the task-3 fixes, so the rules stay on. The same holds for a rule of the type check command itself: `no-generated-empty-object-type` (on by default for `**/*.{ts,tsx}`) or any other `typecheck.config.ts` rule that the pinned run reports takes its off entry in `typecheck.config.ts`, with the same child-issue comment (#709 is the catch-all). `must-use-result` follows decision 4: on for `src/**` with one directive, off for the test globs. A report of a rule this change carries over rather than takes from the preset — the `className` and `.forEach` entries of `eslint-js/no-restricted-syntax`, the vendored `js/recommended` set — is fixed at its site, never turned off, because an off entry would kill the carried-over ban too. The research inventory (`tmp/claude/lint/harness.md` section 3) is the map for what to expect, not the list itself: the tree and the plugin moved since it was taken. A rule with no reports stays on.

4. **`typecheck.config.ts` sets the four consumers and scopes `must-use-result` to `src/**`.** `must-use-result` runs as `['error', { consumers: ['unwrapOrThrow', 'passGate', 'deliverNotice', 'keepSuspendingRefusal'] }]` for `src/**` — PR #676's block, taken verbatim. The parity premise needed one correction, settled by the supervisor decision of this run: the patched ESLint rule never reported a floating awaited `Promise<Result>` (its visitor missed the promise wrapper), and the type check command closes that blind spot — 77 reports on main's tree, 76 of them test files that drop the Result and assert side effects, one deliberate and documented production drop. The decision: the rule turns off for the test globs with the comment that a child of #607 turns it on in tests, where each test asserts the Result instead of dropping it (no issue number — the child is not filed); the rule stays on for `src/**`, and the one production site (`src/workflows/execute-analysis.ts:385`) takes a `typecheck-disable-next-line` directive that carries the adjacent comment's reason — a ledger miss must not fail the run — so the reason is stated once. The four old test directives are deleted, not rewritten: the test glob covers their sites, and a directive that suppresses nothing is itself a problem. The done-when holds: the command reports 0 for `must-use-result`, the same as ESLint did before the move.

5. **`scripts/**/*.ts` enter `tsconfig.json`.** `include` becomes `["src", "scripts/**/*.ts"]` — PR #676's choice, taken with its config. The typed rules then see the scripts with the real types; their reports are off entries of decision 3 like any other. The build is unaffected: `tsconfig.build.json` carries its own include and stays unchanged. Alternative rejected: excluding the scripts from the typed rules — it leaves them permanently untyped, and PR #676's `scripts/refresh-fixtures.ts` changes stay untaken because the rules it fixed are off here. A `tsc` diagnostic in a script (a type error, not a rule report) is fixed at its site if the pinned run surfaces one; that is part of putting the scripts into the program, not a child-issue report fix.

6. **The directives take their settled forms.** The two `no-control-regex` directives in `src/input-sanitization.ts` become `// oxlint-disable-next-line no-control-regex -- <the reason they already carry>`. The four old `must-use-result` directives in the result and hooks tests are deleted — the test glob of decision 4 covers their sites, and a dead directive is noise. One new directive lands at `src/workflows/execute-analysis.ts:385`: `// typecheck-disable-next-line must-use-result -- <the ledger reason>`, the form the type check command reads; the reason is mandatory, a directive that suppresses nothing is a problem, and the adjacent comment does not state the reason twice.

7. **The task-8 fixes are the smallest test-local changes that satisfy the rules.** The category is "the reports that oxlint finds and ESLint missed": the ESLint baseline was green, so every report of `no-unsafe-optional-chaining` (the pinned run gives 11 on main — the research-era inventory knew one, `src/workflows/execute-analysis.test.ts` line 965, the `(failed?.error as string).length` expression; the others sit in `src/report-render` figure and gallery tests, optional chains consumed through casts) and of `typescript/no-misused-promises` (`src/loop/run-to-terminal.test.ts:58`, a comma expression `(names.push(name), fn())`) is fixed at its site. The rule stays on and takes no off entry — it is task 8's own category, no child issue owns it. Both fixes live in test files; the fix changes no production code and no assertion's meaning: it makes an already-assumed presence explicit (for example an assertion of presence, then a non-optional access) or unwraps the comma expression into a block body.

8. **CI keeps the job name and pins its Node.** `lint (harness)` keeps its name, because `release-harness.yml:88` and `release.yml:70` wait for it. The ESLint step becomes the oxlint step (`bun run lint`), the typecheck step runs `bun run typecheck`, and the job gains `actions/setup-node` at the pinned version with Node 24 — the same step the prov-kernel job carries, because the command needs Node 22.18 or later. The root Claude hook needs no edit: it walks up from the edited file to the nearest `oxlint.config.ts`, so harness joins it the moment the config exists.

9. **The text sweep is issue task 10, taken from PR #676's hunks.** `harness/CLAUDE.md` (both paragraphs), the `structured-logging` spec through this change's delta, `src/lib/console-logger.ts`, and `lint.yml` (header and step names) take PR #676's text verbatim. In `src/lib/result.ts` and `src/sandbox/create-sandbox.ts` only the doc-comment hunks that name the lint or the lint patch are taken — the rest of PR #676's changes in those files are rule fixes. The final grep gate: no `eslint` reference remains in harness outside `bun.lock` identifiers, the `eslint-js/` rule-id namespace of `oxlint.config.ts` (the plugin names its rules that way), and the openspec archive.

## Risks / Trade-offs

- [The pinned 0.7.0 run reports rules the 0.3.0 research does not map] → the run itself is the loop's input; each rule id gets the amendment's mapping, and `#709` is the catch-all. A rule with reports that the amendment does not name lands on #709 by construction.
- [`bun install --frozen-lockfile` fails in CI on a stale lock] → the lock is regenerated with the platform binaries of `oxlint` and `oxlint-tsgolint`, and the frozen install is the verification.
- [oxlint lints the git-excluded local scratch tree `harness/tmp/`] → oxlint's ignore traversal reads `.git/info/exclude`; the local `bun run lint` gate runs on the tracked tree and the verification replants nothing in `tmp/`. If a scratch file still reaches the run, the gate records it as local-only noise, not a repository defect.
- [A turned-off rule hides a true positive until its child lands] → accepted by the umbrella's design; the off comment names the owner, and #709 closes the tail.
- [The bun-types exemption masks a real void-return bug in a test] → the exemption is scoped to the two rules and the test globs only, and the type check command still typechecks the tests.
- [`must-use-result` parity drifts because the type check command's matcher differs from the patched wrapper] → found and settled during apply: the matcher is a superset (it sees floating awaited Results). The supervisor decision scopes the rule to `src/**` with one directive, and the acceptance replays the ESLint baseline (0 reports) against `bun run typecheck`; a scratch dropped `Result` in `src/` must fail it, and a consumer-fed `Result` must pass.

## Migration Plan

The change lives on branch `feat/609-harness-oxlint` as working-tree edits; no commit, push, or release happens inside this workflow. Rollback is discarding the working tree. The stack of child PRs (#703 upward) builds on the merged result; each child deletes the off entries it owns.
