## 3a. The emission decisions are extracted so they can be tested

Groups 5.1/5.3/5.6 as originally written assumed the body's emissions were observable from a test. They are not: nothing in this package drives a production workflow body — `sandbox-step.test.ts` covers only the extracted `createLineageCollector`, and `run-event-stream.test.ts` drives a *synthetic* workflow. Reaching `runDataProfileBody` would need a launched engine plus fakes for the sandbox client, a scripted chat provider, an embedder, and a workspace filesystem. The decidable part is therefore lifted out, which is this package's own established answer to an untestable body.

- [x] 5.6 SUBSTITUTED, not dropped. The property is body control flow — where `complete` sits relative to the ledger write and the revoke — so no test short of driving the whole body can reach it, and this package drives no workflow body (see group 3a). It is instead guaranteed **structurally**: `complete()` has two call sites — the empty-manifest path and the full success path — and they are mutually exclusive (the first returns), with each being the LAST statement of its own path, after that path's terminal ledger write and authorization revoke. So exactly one terminal emission is reachable per execution, and anything that throws on the way to either reaches the catch having emitted no terminal at all. That is reviewable at a glance in a way a test result is not, and the placement carries a comment saying why it must stay last
- [x] 5.7 Test that a `running` row whose workflow is gone is recoverable into a fresh profile via the orphan reconcile — this is the bound on the function-id-sequence risk, so it is checked rather than asserted
